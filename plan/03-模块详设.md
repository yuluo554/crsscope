# 03 · 模块详设 — crsscope

> 数值口径只在 `data/README.md` §四定义。本文引用它，**不复制阈值**。
> 架构分层与依赖方向见 `plan/02-架构与技术选型.md`。

五个模块的共同形状：

```
读入 → 归一（统一中间表示）→ 判定（顺序固定）→ 结果对象 → report 渲染
                                    │
                                    └─ 每条结论带 evidence（规则 id / 声明来源 / 边界框来源）
```

**统一结果项**（所有模块共用，`report.py` 定义）：

```python
{
  "check": "magnitude",              # 检查项 id（固定枚举）
  "status": "consistent" | "conflict" | "undecidable" | "info" | "warning" | "error",
  "reason": "magnitude" | "axis" | "unit" | "mixed" | "insufficient_samples" | None,
  "detail": "人类可读的一句话",
  "evidence": {"rule": "EPSG-4326-AXIS", "source": "data/README.md §1.2", ...}
}
```

## 一、模块 M1 `decl.py` — 声明-内容一致性

### 接口

```python
def run(path: Path, declared_crs: str | None, *, strict: bool = False) -> ModuleResult
```

- `declared_crs ∈ {None, "4326", "3857", "4490", "crs84"}`（**GCJ-02 / BD-09 不是合法声明值**，
  传入即 `UsageError` → exit 2；见 `data/README.md` §1.2）。
- 输入：GeoJSON（含 `crs` 成员）/ `.prj` 附属文件 / CSV 点表。

### 判定顺序（固定，不许并行）

1. **量级**（`magnitude`）：按 §4.1 的度域 / 米域 / 中间带三条；
2. **轴序**（`axis`）：只用可判定样本子集，样本数 `< 5` → `undecidable`；
3. **单位**（`unit`）：`declared=3857` 且量级在度域；
4. **混用**（`mixed`）：同一批数据内量级分档冲突；
5. **分布范围**（`extent`）：声明地理坐标系但坐标落在 3857 米域量级。

顺序固定的理由：量级先判可以把"米域 vs 度域"一次性定性，后续轴序判定才不会被米域样本污染。

### 失败路径

| 情况 | 出口 |
|---|---|
| `--declared-crs gcj02` | exit 2（非法枚举，附合法枚举清单） |
| 文件不存在 | exit 3 |
| JSON 不可解析 / 坐标对非数值 | exit 4（逐条记录） |
| 可判定样本 `< 5` | 结果 `undecidable` → exit 5（除非 `--allow-undecidable`） |

### 测试点

- [ ] "声明 4326 + 量级 1e6" 命中 `conflict/magnitude`（**单独**，不靠轴序判据串扰）
- [ ] "声明 4326 + 轴序写反" 命中 `conflict/axis`（**单独**）
- [ ] 全部样本在 ±90 内 → `undecidable/insufficient_samples`
- [ ] 前半段米、后半段度 → `conflict/mixed`
- [ ] 声明 3857 + 度域坐标 → `conflict/unit`

## 二、模块 M2 `detect.py` — 偏移检测与残差

### 接口

```python
def run(path: Path, declared_crs: str | None, mask: Mask | None, *,
        mask_file: Path | None = None) -> DetectResult
```

- 候选假设固定为 `("WGS84", "GCJ02", "BD09")`，**不增不减**。
- 掩膜缺失 → exit 3（**不得**默认"全是陆地"，`data/README.md` §4.3）。

### 判定顺序（固定）

1. **逆变换**：对每个假设 `h` 求 `inverse_h(p)`；
2. **覆盖检查**：样本全在 `out_of_china` 外 → `out_of_coverage`（**不是**"WGS84 胜出"）；
3. **三路评分**（§4.2）：落水率 / 跨界跳变 / 与声明冲突；
4. **排序与置信**：`score` 降序，同分按假设名字典序；
5. **残差三段**：固定 `residual.kind` 枚举齐全；
6. **边界画像**：`boundary_profiles: {coordTransform_py, gcoord}` 各一份判定 + **显式警告两库边界不一致**。

### 输出骨架

```json
{
  "winner": "GCJ02",
  "confidence": "medium",
  "hypotheses": [{"name": "WGS84", "score": 0.12, "offset_m": 0.0, "direction": null, "water_ratio": 1.0},
                 {"name": "GCJ02", "score": 0.97, "offset_m": 412.3, "direction": "NE", "water_ratio": 0.0},
                 {"name": "BD09",  "score": 0.71, "offset_m": 683.9, "direction": "NE", "water_ratio": 0.1}],
  "boundary_profiles": {
    "coordTransform_py": {"in_china": true, "distance_to_boundary_deg": 12.4},
    "gcoord":            {"in_china": true, "distance_to_boundary_deg": 19.1}
  },
  "residual": [{"kind": "formula_approximation", "detail": "...", "affected_points": 40},
               {"kind": "vendor_divergence",     "detail": "...", "affected_points": 40},
               {"kind": "boundary_jump",         "detail": "...", "affected_points": 0}],
  "mask": {"mask_version": "v1", "mask_max_resolution_deg": 1.0,
           "unknown_ratio": 0.0, "coastal_ratio": 0.0, "evaluable_points": 40}
}
```

### 失败路径

| 情况 | 出口 |
|---|---|
| 掩膜缺失 / 步长 > 1° | exit 3 |
| 可判定点 `< 30` | `confidence: undecidable` → exit 5 |
| 全样本在边界外 | 结果 `out_of_coverage`，附两库结论 → exit 5 |
| 候选并列第一 | `undecidable` |

### 测试点

- [ ] D2 类：合成一条被 GCJ-02 偏移的陆上轨迹 → 正确假设把落水率压到近零
- [ ] 边界外样本 → `out_of_coverage`，**不得**硬判 WGS84
- [ ] `residual.kind` 三段齐全（断言集合相等，不是"存在"）
- [ ] 落在两库边界框之间的样本 → 两个 `boundary_profiles` 结论不同

## 三、模块 M3 `xdiff.py` — 跨实现差分

### 接口

```python
def run(path: Path, target: str) -> XDiffResult
```

三个对照实现**全部本地重实现**（不调用外部服务、不引入第三方运行时依赖）：

| 实现 | 逆向 | 前向常数 | 边界框 |
|---|---|---|---|
| `coordTransform_py` | 一步线性近似 | 同下 | `lng ∈ (73.66, 135.05) ∧ lat ∈ (3.86, 53.55)` **开区间** |
| `gcoord` | 定点迭代，容差 `1e-6` | `a=6378245`, `ee=0.006693421622965823` | `lon ∈ [72.004, 137.8347] ∧ lat ∈ [0.8293, 55.8271]` **闭区间** |
| `proj4js-equivalent`（WebMercator） | 解析逆 | — | — |

### 输出

```json
{
  "implementations": [{"name": "coordTransform_py", "points": [[lng, lat], ...]}, ...],
  "pairwise": [{"a": "coordTransform_py", "b": "gcoord",
                "median_m": 0.0, "max_m": 538.2, "p95_m": 412.7, "max_at": [73.2, 39.5]}],
  "boundary_table": [{"lon": 73.2, "lat": 39.5,
                      "coordTransform_py": "outside", "gcoord": "inside", "agree": false}],
  "jumps": [{"lon": 73.2, "lat": 39.5, "reason": "out_of_china 边界内外跳变"}]
}
```

### 失败路径

- 迭代超上限 → **`not_converged`**，不得静默返回（题面 §M3 纪律）。
- `target` 非法 → exit 2；文件缺失 → exit 3。

### 测试点

- [ ] `(73.2, 39.5)` → 两库结论不同（经向分歧）
- [ ] `(112.0, 2.0)` → 两库结论不同（纬向分歧，须 `< 3.86°N`）
- [ ] `(112.0, 5.0)` / `(112.0, 60.0)` → 两库一致
- [ ] 迭代不收敛（构造极端输入）→ `not_converged` 出现在结果里，不抛未捕获异常

## 四、模块 M4 `geojson.py` — RFC 7946 结构与声明审计

### 接口

```python
def run(paths: list[Path], strict_ring: bool = False) -> GeoJSONResult
```

### 检查项与顺序（固定）

| # | 检查项 | 级别 | 条款 |
|---|---|---|---|
| 1 | `ring_order` 环方向（Shoelace） | **warning**（R1+R2 成对引用）；`--strict-ring` 才升 error | §3.1.6 |
| 2 | `axis` 坐标对是否 `lon, lat` | warning | §3.1.1 |
| 3 | `bbox` 顺序 / 与真实外包框一致 / 跨 180° 合法 | warning / info | §7.1、§5.2 |
| 4 | `nesting` GeometryCollection 深度与类型自洽 | error / info | §3.1 |
| 5 | `null_geometry` / `null_properties` | **info**（合法，不得报错） | §3.2 |
| 6 | `crs_member` 存在 → "**no longer used**" | warning | §4、App. B.1 |
| 7 | `precision` 单分量小数位 > 9 | warning | `data/README.md` §4.6 |

### R1/R2 成对引用的实现方式（关键）

`ring_order` 的 `detail` 必须**同时**含两句条款的语义：

- R1：外环逆时针（rh 右手法则）；
- R2：`"For backwards compatibility, parsers SHOULD NOT reject Polygons that do not follow the right-hand rule."`

且**级别由 R2 决定**：默认 `warning`。`--strict-ring` 是**唯一**升级路径。

> **变异靶子**：把 R2 那段逻辑从代码里删掉 → `ring_order` 必须升级为 `error` → 单测必须失败。
> 这条是"假门"的高发点：只断言"报告里有 ring_order"证明不了分级逻辑存在。

### 失败路径

- 非法 JSON → exit 4；`type` 未知 → error 级发现 → exit 4。
- **`geometry: null` / `properties: null` 不得进 exit 4**（合法，只出 info）。

### 测试点

- [ ] check-geojson 明示不查的三项（环方向 / 坐标精度 / `crs`）**本工具都查**
- [ ] R1+R2 成对：删 R2 → 级别升级 → 测试失败（变异）
- [ ] 跨 180° bbox（`[177, -20, -178, -16]`）→ **不得**报 error
- [ ] `geometry: null` → info，且 exit 0
- [ ] 全仓文案不含肯定式 "MUST NOT"（字符串扫描测试）

## 五、模块 M5 `tiles.py` — 瓦片 / 投影一致性

### 接口

```python
def run(path: Path) -> TilesResult
```

输入：`z/x/y` 清单（CSV 或 JSON）或 3857/4326 混用点集。**不做渲染、不产出图片、不做切片**。

### 检查项

| # | 检查项 | 判据 |
|---|---|---|
| 1 | `axis_flip` | 同 `z` 下同时出现 `y` 与 `2^z-1-y` 且指向同一 bbox（§4.7） |
| 2 | `y_range` | `y ∉ [0, 2^z-1]` → error |
| 3 | `zoom_bbox` | `z+1` 覆盖集合 ⊆ `z` 集合展开，破坏即 conflict |
| 4 | `wrap` | `x` 环绕须显式 `wrap: true`；经纬跨日界线而缺席 → conflict |
| 5 | `mixed_3857_4326` | 同一集合内量级分档冲突 |

### 测试点

- [ ] `y` 轴翻转**静态**检出（无需任何底图）
- [ ] 混用样本给出具体冲突点（坐标 + `z/x/y`）
- [ ] `y` 越界 → error，且单点即判

## 六、`report.py` — 双轨渲染

### 接口

```python
def render(result: ModuleResult, fmt: str = "both", out_dir: Path | None = None) -> dict[str, str]
def dumps_json(payload: dict) -> str      # sort_keys=True, ensure_ascii=False
def fmt_float(value: float, digits: int = 1) -> str
def scrub(text: str) -> str               # 去绝对路径 / 用户名 / 主机名
```

- **`report.md` 与 `report.json` 必然同源**：同一份 `payload` 渲染两次。
- `report.md` 必须含：结论摘要 → 逐检查项表 → 证据 → **已知边界**（掩膜分辨率 / 不可消解残差 / 不做渲染）。

### 测试点

- [ ] 同一 payload 双跑 `dumps_json` 逐字节相等
- [ ] payload 不含绝对路径（构造一个带 `C:\...` 的输入 → scrub 后消失）
- [ ] `--json` 与 `report.md` 的退出码相同

## 七、`cli.py` — 参数面

```
crsscope decl    <file> --declared-crs {4326,3857,4490,crs84} [--json] [--fail-on ...] [--allow-undecidable]
crsscope detect  <file> [--declared-crs ...] [--mask <file>] [--json] ...
crsscope xdiff   <file> --target {wgs84,gcj02,bd09,webmercator} [--json]
crsscope geojson <file>... [--strict-ring] [--json]
crsscope tiles   <file> [--json]
crsscope report  <report.json>... [--json]      # 汇总与门禁
```

### 失败路径与退出码

`data/README.md` §4.9 是全项目唯一映射。实现方式：`errors.py` 里定义

```python
class CrsscopeError(Exception): code: int
class UsageError(CrsscopeError): code = 2
class EnvironmentMissing(CrsscopeError): code = 3
class InvalidInput(CrsscopeError): code = 4
class Undecidable(CrsscopeError): code = 5
class FindingsHit(CrsscopeError): code = 1
```

`cli.main()` 是**唯一**把异常转成退出码的地方（`argparse` 的 `SystemExit(2)` 单独捕获）。

### 测试点

- [ ] 每个子命令 `--help` exit 0
- [ ] 未知子命令 → exit 2
- [ ] 文件不存在 → exit 3
- [ ] `--declared-crs gcj02` → exit 2，提示合法枚举
- [ ] 退出码优先级 `2 > 3 > 4 > 5 > 1 > 0` 逐位断言
