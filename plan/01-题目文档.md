### 2.2 RFC 7946 实读原文（✅ `curl https://www.rfc-editor.org/rfc/rfc7946.txt`，HTTP 200，49143 bytes）

| # | 条款 | 原文（照录） | 位置 |
|---|---|---|---|
| R1 | 外环逆时针（**MUST**） | "A linear ring MUST follow the right-hand rule with respect to the area it bounds, i.e., exterior rings are counterclockwise, and holes are clockwise." | §3.1.6（txt 行 468–474；§7.1 行 1446 重述） |
| R2 | **紧接着的一句，对校验器极关键** | "For backwards compatibility, parsers SHOULD NOT reject Polygons that do not follow the right-hand rule." | §3.1.6 同段 |
| R3 | 轴序 `lon, lat` | "The first two elements are longitude and latitude, or easting and northing, precisely in that order and using decimal numbers." | §3.1.1 |
| R4 | bbox 与跨 180° | `"[west, south, east, north]"`；跨 180° 时"northeast corner longitude **小于** southwest corner longitude"是合法的 | §7.1（txt 行 1449）、§5.2 斐济例子 `[177.0,-20.0,-178.0,-16.0]` |
| R5 | **`crs` 成员：没有 "MUST NOT"** | §4 只说坐标系是 WGS 84 / `urn:ogc:def:crs:OGC::CRS84`，替代坐标系 "has been removed from this version…"，并留活口 "where all involved parties have a prior arrangement, alternative coordinate reference systems can be used"；Appendix B.1 只说 'the "crs" member of [GJ2008] is no longer used' | §4、Appendix B.1 |
| R6 | null geometry / null properties | Feature 的 geometry 可为 JSON `null`（"in the case that the Feature is unlocated"）；properties 可为 JSON object 或 `null` | §3.2 |

> ⚠️ **本仓纪律**：R1 与 R2 必须**成对引用**——只引 R1 会做出"拒绝合法历史数据"的校验器；只引 R2 会放过真正的方向错误。
> ⚠️ **纠错留档**：一次性 WebFetch 摘要曾声称 §4 有 "crs MUST NOT"——**实读原文没有该强制条款**。本仓按实读原文表述，**禁止在任何文档/代码/提示中出现 "crs MUST NOT"**（见 `plan/00` 决策记录 ①）。

### 2.3 EPSG 轴序陷阱（✅ `epsg.io/<code>.json` 实读 PROJJSON，非二手转述）

| EPSG | 名称 | 类型 | 注册表轴序 | 单位 |
|---|---|---|---|---|
| **4326** | WGS 84 | GeographicCRS | **Geodetic latitude: north, Geodetic longitude: east**（即 **lat 在前**） | degree |
| **3857** | WGS 84 / Pseudo-Mercator | ProjectedCRS | Easting: east, Northing: north | **metre** |
| **4490** | CGCS2000 | GeographicCRS | 同 4326（**latitude 在前**） | degree |

- **可确证的陷阱**：EPSG 注册表里 4326 是 **(lat, lon)**，GeoJSON / RFC 7946 是 **(lon, lat)**；3857 单位是**米**、4326 是**度**。两者都"看起来对"，因为海岸线形状不变。
- **GCJ-02 / BD-09 未在 EPSG 注册（无 EPSG 代码）**。实证：`gh search code 'gcj repo:OSGeo/PROJ'` → **0 命中**；对照组 `'Pseudo-Mercator repo:OSGeo/PROJ'` → **3 命中**（证明 code search 本身正常，0 不是检索失灵）。

### 2.4 GCJ-02：两个主流实现的"中国边界"互不相同（✅ 实读源码，非传闻）

| 实现 | 星数 | 判定函数 | 边界框（源码原文） | 逆向算法 |
|---|---|---|---|---|
| `wandergis/coordTransform_py` | 1234★ | `out_of_china` | `lng ∈ (73.66, 135.05)` **且** `lat ∈ (3.86, 53.55)` | **一步线性近似**：`return [lng*2 - mglng, lat*2 - mglat]` |
| `hujiulong/gcoord` | 3324★ | `isInChinaBbox` | `lon ∈ [72.004, 137.8347]` **且** `lat ∈ [0.8293, 55.8271]` | **定点迭代**：`while (Math.abs(dx) > 1e-6 \|\| Math.abs(dy) > 1e-6)`；前向常数 `a = 6378245`、`ee = 0.006693421622965823` |

- 两个"中国边界"判定框**互不相同**（经度 73.66–135.05 vs 72.004–137.8347；纬度 3.86–53.55 vs 0.8293–55.8271）→ **同一坐标（如新疆西部 73.2°E、南沙一带低纬点）在不同库下"是否偏移"结论不同**。这是**可复现、可验证的审计发现点**，不是任何一方的 bug。
- 性质：HN 用户引官方名"地形图非线性保密处理算法"，称其 "deliberately obfuscated with a **nonlinear** transform"（原话见 §2.5）。
- **逆向精度诚实边界**（必读）：数值逆向**可解**（迭代收敛容差 1e-6° ≈ 0.1 m）；**不可消解的不确定性**有三条——(a) 民间公式只是对未公开实现的近似；(b) 厂商实现（高德 / Google 中国 / 腾讯）差异可达**米级**；(c) `out_of_china` 边界两侧存在**跳变**。因此本工具**必须输出"残差 + 置信 / 边界风险"，禁止宣称唯一真值**。

## 三、任务要求

统一约定（五模块共用，写进 CLI `--help` 与 `README.md`）：

- **输入**：本地文件（GeoJSON / GPX / `.prj` / CSV 点表）+ 命令行声明（`--declared-crs`）。**运行期零网络**。
- **输出**：`report.json`（机器可复算）+ `report.md`（人读）。每条结论带 `evidence`（命中的规则 id / 声明来源 / 边界框来源）。
- **确定性纪律**：不读系统时钟做判定、不联网、不随机、字典键序固定、浮点统一格式化、两次运行字节级一致；输出不含主机名 / 绝对路径 / 用户名。
- **数值口径**：全部阈值、评分、残差格式、灰区条件、退出码**一处定义在 `data/README.md` §四**，代码与文档只可引用，不得另立第二套。
- **结论纪律**：报告必须同时给**判定 + 置信 + 不可消解残差声明**；不确定即输出 `undecidable`，**不得硬判**。

### M1 声明-内容一致性判定

- **输入**：数据文件（GeoJSON 带 `crs` 成员 / `.prj` 附属文件 / CSV 点表）+ 命令行声明 `--declared-crs <EPSG|name>`。
- **输出**：逐检查项判定 `consistent` / `conflict` / `undecidable`，附证据：
  1. **量级**：声明为度制（4326 / 4490）但坐标量级是米（`|v| ≥ 1e5` 量级）→ `conflict`；
  2. **轴序**：声明 4326/4490 但样本呈现 `(lat, lon)` 排列（纬度分量越过 ±90、且经度分量落在 ±90 内）→ `conflict`，并给出"疑似轴序颠倒"与纠正后的样本；
  3. **分布范围**：声明为地理坐标系但坐标落在 3857 米域量级、或声明的 CRS 与该数据 WGS84 外包框明显不符 → `undecidable` + 建议候选；
  4. **4490 / 4326 / 3857 混用**：同一批数据内出现两种口径的统计证据（如部分点量级为米、部分为度）→ `conflict`（`mixed`）。
- **确定性纪律**：轴序判定只用**可判定的样本子集**（两分量都在 ±180 内），可判定样本数不足则 `undecidable`；阈值与样本数下限引 §4.1。
- **验收**：构造"**声明 4326 但坐标量级 1e6**"样本必须命中；"**声明 4326 且坐标写反轴序**"必须命中；**两组样本各自单测**，不得靠同一判据串扰命中。

### M2 GCJ-02 / BD-09 偏移检测与残差报告

- **输入**：点集 / 轨迹（GeoJSON、GPX、CSV）+（可选）声明 CRS。
- **输出**：对候选假设 **{WGS84, GCJ02, BD09}** **各算一遍**，输出：
  - `winner`（排序第一的假设）+ `confidence`（`high` / `medium` / `low` / `undecidable`）；
  - 每个假设下的 **`offset_m`（相对输入的平均位移）+ 方向**；
  - **不可消解残差声明**（三段固定文案：民间公式近似 / 厂商米级差异 / 边界两侧跳变）；
  - **边界风险**：明确列出本样本到两个库边界框的距离，并**显式警告"两库边界不一致"**（`boundary_profiles: {coordTransform_py, gcoord}` 各一份判定）。
- **评分维度**（三路，权重与阈值见 §4.2）：
  1. **落陆地 / 落水**：把假设的逆变换结果投到**离线低分辨率陆地/水域掩膜**上，统计落水比例（D2 的"人不会在湖里跑步"）；
  2. **跨界跳变**：假设要求"跨过 `out_of_china` 边界"才能解释数据 → 降权 + 标 `boundary_jump`；
  3. **与声明 CRS 冲突**：假设与 `--declared-crs` 矛盾 → 降权 + 标 `declared_conflict`。
- **确定性纪律**：掩膜为**仓库内构造的极低分辨率网格**，分辨率上限在报告中声明（首期上限 **1°**，见 §4.3）；掩膜内"未知格 / 海岸带"不计入分母；可判定点不足下限 → `undecidable`；**不联网、不调用任何厂商 API**。
- **验收**：D2 类"**轨迹落在水面**"场景可复现（合成一条被 GCJ-02 偏移的陆上轨迹，正确假设应把落水率压到近零）；**边界框外坐标必须输出"不在算法覆盖范围"而非硬判**；样本落在两库边界框之间时，两个 `boundary_profiles` 的结论必须不同。

### M3 跨工具差分

- **输入**：同一批坐标（点集）+ 目标坐标系。
- **输出**：把同一坐标分别喂给 **gcoord 算法 / coordTransform_py 算法 / proj4js 等价投影的本地重实现**（**本地算法重实现，不调用外部服务、不引入第三方运行时依赖**），报告：
  - 两两差异（米，按 §4.4 距离口径）；
  - 每个实现输出的绝对坐标；
  - **跳变点**：哪些坐标点因落在某实现的 `out_of_china` 边界内外，导致输出从"偏移"跳到"不偏移"；
  - **两库边界结论表**（哪些点两库一致、哪些不一致）。
- **确定性纪律**：算法常数原样写进代码并注明来源（`a = 6378245`、`ee = 0.006693421622965823`；`out_of_china` 两套边界）；迭代容差 `1e-6`；超迭代上限即报 `not_converged`，**不得静默返回**。
- **验收**：**新疆西部 73.2°E** 一类样本必须报出"两库结论不同"（该点对 `coordTransform_py` 的 `lng > 73.66` 不成立 → 不偏移；对 `gcoord` 的 `lon ≥ 72.004` 成立 → 偏移）；纬度方向须构造 **< 3.86°N** 的样本才构成第二类分歧（见 §4.5 的口径说明）。

### M4 GeoJSON RFC 7946 结构与声明审计

- **输入**：一个或多个 GeoJSON 文件（`FeatureCollection` / `Feature` / 几何对象）。
- **输出**：逐项检查 + 条款引用：
  1. **环方向**：外环 CCW / 内环 CW（Shoelace 符号）。命中 R1 违规时**必须同时引用 R2**（"解析器 SHOULD NOT 拒绝"），并据此**分级为 warning 而非 error**；
  2. **轴序**：坐标对是否呈 `lon, lat`（越界分量检测）；
  3. **bbox**：`[west, south, east, north]` 顺序、是否与几何真实外包框一致、**跨 180° 是否合法**（`west > east` 时为合法跨日界线，不是错误）；
  4. **嵌套层数**：`GeometryCollection` / 多层嵌套的深度与类型自洽；
  5. **null geometry**：Feature 的 `geometry: null` 合法（"unlocated"），`properties: null` 合法——**不得报错**；
  6. **`crs` 成员**：按 R5 表述为"**不再使用**（`no longer used`）"，给出"本文件声明了 `crs`，RFC 7946 已不再使用该成员"的 **warning**，并附 R5 的"prior arrangement 可用替代 CRS"一句；**严禁写成 MUST NOT**；
  7. **坐标精度**：有效数字过多（check-geojson 明示不查）→ warning。
- **确定性纪律**：检查项顺序固定；同一文件双跑逐字节一致；`error` 与 `warning` 分级规则一处定义（§4.6）；不得因 R2 而放弃 R1 的**报告**，只影响**严重级别**。
- **验收**：check-geojson 明确不查的三项（**环方向 / 坐标精度 / `crs`**）本工具**必须都查**；R1+R2 成对引用的行为可被单测咬住（把 R2 删掉 → 环方向必须升级为 error，测试应失败）。

### M5 瓦片 / 投影一致性

- **输入**：瓦片坐标清单（`z/x/y`）或 3857/4326 混用的点集。
- **输出**（**仅作为报告中的一个检查项，不做可视化**）：
  1. **XYZ vs TMS**：`y` 轴翻转错误可静态检出（同一 bbox 下 `y` 与 `2^z-1-y` 同时出现 → 混用）；
  2. **zoom ↔ bbox**：给定 bbox 的覆盖瓦片数与 `z` 单调性自洽；
  3. **3857 / 4326 混用**：同一集合内量级分档冲突；
  4. **跨 180°**：瓦片跨越日界线时 `x` 环绕是否被正确处理。
- **确定性纪律**：不做地图渲染、不产出图片、不做切片；输出只有布尔/数值判定与证据。
- **验收**：`y` 轴翻转错误可**静态**检出（不需要任何底图）；混用样本给出具体冲突点。

### 扩展项（明确列二期，不进首期判定路径）

- 多源回归（同一批点，多份声明互相对账）；
- 更多加密坐标系（如地方独立坐标系的启用）；
- 掩膜分辨率提升（见 §4.3 上限）。
- **时间轴永远不进**：时间戳只作为"速度无法判定"这一从属输入的来源。

## 七、边界与非目标

- **不做纯坐标转换库 / 服务**：coordtransform **4654★** / gcoord **3324★** 已饱和。转换只作为 **M3 的对照实现**存在于仓库内，不对外提供 `convert` 命令，不发布包对外承诺 API 稳定性。
- **不做纯瓦片换算工具**：mercantile **452★** / geojson-vt **2081★** 已覆盖，且需求证据最弱（v2ex 与 HN 侧无强原话）→ **降为 M5 的一个检查项**，且**不做切片引擎**。
- **不做 GPX 编辑器 / 可视化 / 3D 回放**：gpxpy **1106★** / GPSBabel **553★** 已占，且会滑入可视化禁区 → 只保留"**物理可行性判定**"这一从属检查（缺时间戳 → 速度无法判定 → 落水启发式降级）。
- **不做完整 GIS 几何校验**：shapely/GEOS **4533★**、turf `booleanValid` **10526★** 已占，且会滑向数学形式化。本工具只查与**参考系语义**相关的项。
- **不做纯 GeoJSON 单文件浏览器校验器**：Show HN **2026-09-21** 已有直接先例（P1），做浏览器版 = 同质竞争且滑向可视化 → **保留其语义检查项为 M4**，形态改 **CLI / CI 批量审计**，靠 M1/M2/M3 差异化。
- **不做栅格瓦片渲染 / 切片引擎**：与"审计"无关，且 M5 明确不做可视化。
- **不把"点落海里判坐标系"独立成题**：那只是 M2 的一个评分维度，单独立题会退化成噱头。
- **隐私红线**：**纯本地、零网络**。不下载掩膜、不上传坐标、不写遥测；报告不写绝对路径 / 主机名 / 用户名。M2 的水陆判定必须用**仓库内离线掩膜**，并**声明分辨率上限**（首期 1°，见 §4.3）——分辨率不足时输出 `undecidable`，不得把"掩膜看不见的湖"当作"陆上正确"。
- **算法纪律**：两库边界框与常数**原样照录并注明来源**；**不复制任何未公开实现**，不声称逆向出官方算法。
- **结论纪律**：GCJ-02 逆向的结论永远是"**在某组假设下的残差与置信**"，**禁止宣称唯一真值**（§2.4 三条不可消解不确定性）。
- **时间轴纪律**：时间戳只是从属输入，**不做时间语义主线**（见 §一 切割声明）。
- **品牌隔离**：本系列其他项目不得在文档、代码、提交信息中被提及。
- **首期范围**：五个检查模块 + 五种子命令；不做多源回归、不做地方独立坐标系、不做掩膜升级。
